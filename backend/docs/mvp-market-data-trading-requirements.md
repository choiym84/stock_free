# Stock Free MVP 시장 데이터 및 모의투자 요구사항

- 문서 상태: 확정
- 작성일: 2026-08-27
- 대상 단계: 1차 MVP
- 대상 시장: 국내주식 KRX 정규장
- 시세 제공자: 한국투자증권(KIS) Open Trading API

## 1. 목표

Stock Free MVP는 운영자가 지정한 소수 종목의 실시간 호가를 사용자에게 전달하고, 해당 호가를 기준으로 시장가 모의투자를 제공한다.

동시에 실시간 체결 데이터를 1분 OHLCV 봉으로 집계해 PostgreSQL에 지속적으로 저장한다. 저장된 1분봉은 차트에서 과거 방향으로 계속 조회할 수 있어야 한다.

## 2. MVP 범위

### 포함

- 운영자가 직접 지정한 종목만 시세 수집
- KRX 정규장 시세만 처리
- KIS WebSocket을 통한 실시간 체결가 및 호가 수신
- 서버 WebSocket을 통한 클라이언트 실시간 시세 전송
- 실시간 체결 데이터를 이용한 1분 OHLCV 생성
- 완성된 1분봉의 PostgreSQL 영구 저장
- 시간 커서 기반 과거 1분봉 조회
- 최우선 호가를 사용하는 시장가 모의주문
- 매수·매도 전량 즉시 체결 또는 전량 거절
- 계좌 잔액, 보유 수량 및 거래 이력 갱신

### 제외

- 지정가 주문
- 부분 체결
- 주문 대기 및 주문 취소
- 실제 호가 잔량을 반영한 체결
- 공매도
- 미수·신용거래
- 소수점 단위 주식 거래
- 정규장 외 거래
- 서버가 하루 이상 중단된 경우의 과거 분봉 완전 복구
- 수수료 및 세금 부과
- 모든 실시간 체결 틱의 DB 영구 저장

## 3. 전체 데이터 흐름

```text
KIS WebSocket
    │
    ├─ 실시간 호가 ──→ 최신 호가 캐시 ──→ 주문 체결 가격 결정
    │                         └──────────→ 클라이언트 WebSocket
    │
    └─ 실시간 체결 ──→ 현재 1분봉 메모리 집계
                              │
                              └─ 봉 완성 ──→ PostgreSQL

KIS 당일 분봉 REST API
    └─ 재연결·애플리케이션 재시작·짧은 누락 보정에만 사용
```

프론트엔드는 KIS API에 직접 접속하지 않는다. KIS 인증정보와 실제 체결 기준 가격은 서버에서만 관리한다.

## 4. 수집 대상 종목

- 운영자가 수집 대상 종목을 직접 활성화하거나 비활성화한다.
- 수집 대상이면서 거래 가능한 종목만 KIS WebSocket을 구독한다.
- 종목을 활성화한 시점부터 실시간 데이터를 수집한다.
- 장중에 종목을 새로 활성화하면 KIS 당일 분봉 REST API를 이용해 당일 데이터의 가능한 범위를 우선 보충하고, 이후 WebSocket 데이터로 이어서 수집한다.
- 종목을 비활성화하면 신규 데이터 수집과 신규 주문만 중단한다.
- 비활성화 전에 저장한 1분봉과 거래 이력은 삭제하지 않는다.

## 5. 거래 시간

- MVP는 KRX 정규장만 지원한다.
- 정규장이 아닌 시간에는 신규 주문을 거절한다.
- 휴장일, 임시 휴장, 개장 시간 변경은 시장 캘린더 또는 KIS 시장 상태를 기준으로 판단한다.
- 서버 로직에서 단순히 평일 및 고정 시각만으로 장 운영 여부를 확정하지 않는다.
- 저장 시각은 `TIMESTAMPTZ`를 사용하고, 시스템 내부 기준 시각은 명확하게 통일한다.
- 사용자 화면에는 Asia/Seoul 기준 시각으로 표시한다.

## 6. 실시간 호가

### 저장 위치

- 최신 호가는 PostgreSQL에 매 틱 저장하지 않는다.
- 단일 서버 MVP에서는 애플리케이션 메모리 캐시에 저장한다.
- 서버가 여러 대로 확장되면 Redis와 Pub/Sub 또는 동등한 공유 구조로 전환한다.

### 필수 데이터

- 종목 식별자
- 최우선 매수호가
- 최우선 매도호가
- KIS 시세 시각
- 서버 수신 시각
- 데이터 출처

### 유효성

- 정규장 중 서버 수신 시각 기준 최근 5초 이내의 호가만 주문에 사용할 수 있다.
- 호가가 없거나 마지막 수신 후 5초를 초과하면 해당 호가는 오래된 데이터로 판단한다.
- 오래된 호가로는 주문을 체결하지 않고 `MARKET_DATA_UNAVAILABLE` 사유로 거절한다.
- KIS WebSocket 연결이 끊기면 기존 호가를 계속 유효한 것처럼 사용하지 않는다.

## 7. 클라이언트 실시간 전송

- 클라이언트는 필요한 종목만 서버 WebSocket으로 구독한다.
- 서버는 사용자가 구독하지 않은 종목의 시세를 해당 사용자에게 보내지 않는다.
- 서버는 KIS에서 받은 모든 이벤트를 무제한 전달하지 않고 종목별 최신 값을 합칠 수 있다.
- 초기 전송 주기는 최대 약 200ms 간격으로 제한하며 설정으로 변경할 수 있게 한다.
- 클라이언트는 서버가 전달한 가격을 화면 표시에만 사용한다.
- 주문 체결은 클라이언트가 전달한 가격이 아니라 서버가 보유한 최신 유효 호가로 처리한다.

## 8. 1분봉 생성

### 집계 기준

1분 동안 수신한 실시간 체결 데이터를 다음 값으로 집계한다.

- `open_price`: 해당 분의 첫 체결가
- `high_price`: 해당 분의 최고 체결가
- `low_price`: 해당 분의 최저 체결가
- `close_price`: 해당 분의 마지막 체결가
- `volume`: 해당 분의 체결 수량 합계

거래량은 KIS 메시지의 필드 의미를 확인해 개별 체결량을 합산하거나 누적 거래량의 차이를 계산한다. 누적 거래량을 매 이벤트마다 단순 합산해서는 안 된다.

### 봉 확정

- 봉 시간은 분 단위로 절삭한 시각을 사용한다.
- 다음 분의 체결이 수신되거나 분 종료 후 일정 시간이 지나면 이전 봉을 확정한다.
- 초기 확정 지연은 분 종료 후 5초로 한다.
- 확정된 봉만 PostgreSQL에 저장한다.
- 진행 중인 봉은 메모리에서 관리하고 DB의 확정 봉과 구분한다.
- 동일 종목과 동일 분의 봉이 다시 들어오면 중복 생성하지 않고 upsert한다.

### 거래가 없는 분

- 해당 분에 체결이 한 건도 없으면 DB 행을 생성하지 않는다.
- 거래량이 0인 가짜 OHLCV를 DB에 생성하지 않는다.
- 차트에서 연속된 선이 필요하면 프론트엔드 또는 조회 응답 조립 단계에서 이전 종가를 이용해 표현할 수 있다.

## 9. 분봉 보정

- KIS WebSocket이 정상인 동안에는 WebSocket 집계를 주 데이터로 사용한다.
- KIS 당일 분봉 REST API를 종목마다 매분 호출하지 않는다.
- WebSocket 재연결, 애플리케이션 장중 재시작 또는 짧은 누락 감지 시 당일 분봉 REST API로 보정한다.
- 장 종료 후 당일 데이터의 누락 여부를 최종 확인할 수 있다.
- REST로 받은 봉도 동일 기본 키를 이용해 upsert한다.
- 다음 거래일에 전일 분봉을 KIS에서 다시 받을 수 있다고 가정하지 않는다.
- 하루 전체 장애 또는 장기 중단 데이터의 완전 복구는 MVP에서 보장하지 않는다.

## 10. 분봉 저장 및 보관

### 저장 모델

논리 테이블 이름은 `stock_minute_candles`로 한다.

필수 컬럼:

- `stock_id`
- `candle_time`
- `open_price`
- `high_price`
- `low_price`
- `close_price`
- `volume`
- `source`
- `created_at`
- `updated_at`

기본 키 또는 유일 키:

```text
(stock_id, candle_time)
```

### 보관 정책

- MVP에서는 1분봉을 7일 뒤 자동 삭제하지 않는다.
- 수집을 시작한 이후 데이터를 지속해서 보관한다.
- 실제 운영 데이터와 저장 용량을 관찰한 뒤 보관 기간을 다시 결정한다.
- 필요해지면 월 단위 파티셔닝, 오래된 데이터 아카이빙 또는 보관 기간 정책을 도입한다.
- KIS에서 과거 분봉을 다시 제공받기 어렵기 때문에 용량 측정 전 선제 삭제하지 않는다.

## 11. 차트 조회

- 1분봉 차트는 PostgreSQL에 저장된 확정 봉을 조회한다.
- 과거 방향 무한 스크롤은 OFFSET이 아닌 시간 기반 커서 페이지네이션을 사용한다.
- 기본 정렬 기준은 `candle_time`이다.
- 동일 시각 중복을 막기 위해 `(stock_id, candle_time)` 유일성을 DB에서 보장한다.

예시 요청:

```http
GET /api/v1/stocks/{stockId}/candles/1m?before={candleTime}&limit=500
```

차트 조회 캐시 기본안:

- 장중 최근 구간: 15초
- 과거 확정 구간: 더 긴 TTL 적용 가능
- 단일 서버 MVP: Caffeine 또는 동등한 로컬 캐시
- 다중 서버 전환 시: Redis 검토

## 12. 시장가 모의주문

### 지원 주문

- MVP는 시장가 매수와 시장가 매도만 지원한다.
- 지정가 주문은 후속 개선사항으로 분리한다.
- 시장가 주문은 접수 시점의 서버 최신 유효 호가로 즉시 전량 체결한다.

### 체결 가격

- 시장가 매수: 최우선 매도호가
- 시장가 매도: 최우선 매수호가
- 화면에 표시된 호가 잔량은 체결 가능 수량 계산에 사용하지 않는다.
- 요청 수량 전체를 하나의 체결 가격으로 체결한다.
- 부분 체결은 발생하지 않는다.

예:

```text
주문: 10주 시장가 매수
최우선 매도호가: 70,000원
표시 매도 잔량: 3주

MVP 결과: 10주 전량을 주당 70,000원에 즉시 체결
```

이 규칙은 실제 거래소 체결 모델을 재현하는 것이 아니라 MVP 모의투자를 단순화한 정책이다.

### 주문 검증

주문 체결 전에 다음 조건을 모두 확인한다.

- 정규장 운영 중인지 확인
- 수집 및 거래가 활성화된 종목인지 확인
- 주문 수량이 1 이상의 정수인지 확인
- 최근 5초 이내의 유효한 최우선 호가가 있는지 확인
- 매수 계좌의 현금 잔액이 충분한지 확인
- 매도 계좌의 보유 수량이 충분한지 확인
- 동일 계좌에서 같은 `client_order_id`가 이미 처리되지 않았는지 확인

하나라도 만족하지 않으면 주문 전체를 거절한다.

### 비용

- MVP의 거래 수수료는 0원이다.
- MVP의 거래세 및 기타 비용은 0원이다.
- 향후 비용 정책을 추가할 수 있도록 체결금액과 비용을 분리할 수 있는 데이터 구조를 고려한다.

### 주문 상태

- 정상 체결: `EXECUTED`
- 검증 실패 또는 시세 사용 불가: `REJECTED`
- 즉시 체결 모델이므로 장기간 유지되는 `PENDING` 주문은 없다.
- 즉시 체결되므로 주문 취소 기능은 제공하지 않는다.

## 13. 원자성 및 중복 방지

한 주문의 다음 변경은 하나의 DB 트랜잭션으로 처리한다.

- 주문 기록 생성 또는 갱신
- 계좌 현금 잔액 변경
- 보유 수량 및 평균단가 변경
- 계좌 거래 내역 생성
- 보유 종목 거래 내역 생성

중간 단계가 실패하면 전체 변경을 롤백한다.

- `(account_id, client_order_id)` 유일성을 DB에서 보장한다.
- 같은 요청이 재전송되어도 중복 체결하지 않는다.
- 계좌 및 보유 종목의 동시 주문 충돌을 막기 위해 낙관적 버전 또는 명시적인 잠금 정책을 적용한다.
- 현금 잔액과 보유 수량이 음수가 되지 않도록 서비스 검증과 DB 정합성을 함께 보장한다.

## 14. 주문 기록

체결된 주문에는 최소한 다음 정보를 남긴다.

- 주문 ID
- 클라이언트 주문 ID
- 계좌 ID
- 종목 ID
- 매수·매도 구분
- 요청 수량
- 체결 수량
- 체결 단가
- 총 체결금액
- 수수료
- 세금
- 주문 상태
- 거절 사유
- 주문 시각
- 체결 시각
- 체결에 사용한 호가의 KIS 시세 시각
- 서버가 호가를 수신한 시각

## 15. 장애 처리

- KIS WebSocket 연결이 끊기면 자동 재연결한다.
- 재연결 후 운영자가 지정한 수집 대상 종목을 다시 구독한다.
- 연결이 끊긴 동안 최신 호가는 5초가 지나면 무효화한다.
- 유효 호가가 없을 때 주문을 추정 가격으로 체결하지 않는다.
- 짧은 연결 중단은 당일 분봉 REST API를 이용해 가능한 범위에서 보정한다.
- 장기 중단에 대한 완전한 분봉 복구는 MVP 요구사항이 아니다.

## 16. 주요 거절 코드

- `MARKET_CLOSED`: 정규장 운영 시간이 아님
- `STOCK_NOT_TRADABLE`: 거래 대상 종목이 아님
- `INVALID_QUANTITY`: 주문 수량이 유효하지 않음
- `MARKET_DATA_UNAVAILABLE`: 호가가 없거나 5초보다 오래됨
- `INSUFFICIENT_CASH`: 매수 가능 현금 부족
- `INSUFFICIENT_HOLDING`: 매도 가능 수량 부족
- `DUPLICATE_ORDER`: 이미 처리된 클라이언트 주문 ID
- `ORDER_PROCESSING_FAILED`: 처리 중 내부 오류 발생

## 17. 운영 관찰 항목

- KIS WebSocket 연결 상태
- 마지막 메시지 수신 시각
- 종목별 마지막 유효 호가 시각
- 구독 중인 종목 수
- 분봉 생성 및 저장 건수
- 누락 분봉 감지 건수
- REST 보정 성공·실패 건수

- 주문 트랜잭션 실패 건수

## 18. MVP 완료 조건

- 운영자가 종목 수집을 활성화하거나 비활성화할 수 있다.
- 활성화된 종목의 실시간 호가가 클라이언트 화면에서 움직인다.
- KIS 체결 데이터로 완성된 1분 OHLCV가 생성된다.
- 생성된 봉이 중복 없이 PostgreSQL에 저장된다.
- 사용자가 과거 방향으로 스크롤하며 저장된 1분봉을 조회할 수 있다.
- 유효한 호가가 있을 때 시장가 주문이 최우선 상대 호가로 전량 체결된다.
- 호가가 없거나 5초보다 오래되면 주문이 거절된다.
- 매수·매도 후 잔액, 보유 수량 및 거래 이력이 하나의 트랜잭션으로 일관되게 변경된다.
- 같은 `client_order_id` 요청을 반복해도 중복 체결되지 않는다.
- KIS WebSocket 재연결 후 대상 종목 구독이 복구된다.
